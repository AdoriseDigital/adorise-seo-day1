1. Process Assessment Checklist

Complete this for EVERY recurring process in your business. Use a spreadsheet.

Discovery (Do this first)

List all processes: daily, weekly, monthly, quarterly
Interview each team member: "What do you do repeatedly?"
Shadow 3 people for 2 hours each — watch actual work
Document: trigger → steps → output → handoff for each process

Data Collection (Per Process)

Process name & owner
Frequency (times/day, week, month)
Average time per execution (minutes)
Number of people involved
Systems/tools used (list all)
Input type: structured (forms, API) vs unstructured (email, PDF, chat)
Decision points: how many human judgments per run?
Exception rate: % of runs needing special handling
Error rate: % of runs with mistakes
Cost per run: (time × hourly rate) + error costs + opportunity costs
Pain score (1-10): how much does the team hate this?

2. Prioritization Matrix

Score each process 1-10 on four dimensions:

DimensionQuestionHigh Score (8-10)Low Score (1-3)
Automation PotentialRules-based? Structured data? Repetitive?Clear rules, digital inputs, same every timeJudgment-heavy, unstructured, varies
Business ImpactTime × frequency × cost × strategic valueHigh volume, expensive, customer-facingLow volume, cheap, internal only
Technical FeasibilityAPIs? Clean data? Standard formats?Modern SaaS, APIs, clean CRM dataLegacy systems, paper, messy data
Change ReadinessTeam buy-in? Documentation? Sponsor?Team wants it, documented, executive sponsorResistance, tribal knowledge, no sponsor

Calculate Priority Score

(Automation Potential + Business Impact) / (11 - Technical Feasibility + 11 - Change Readiness)
Rank all processes by score
Select top 3 for Phase 1 (30-day sprint)
Select next 5 for Phase 2 (60-day)
Park the rest — revisit quarterly

3. Technical Readiness Checklist

Before building, verify these for your top 3 processes:

Data Readiness

Inputs are digital (forms, webhooks, API, email parsing)
Required fields defined and validated at source
CRM/data source has <5% missing critical fields
Duplicate rate <2% in source systems
Data mapping documented: source field → target field

System Connectivity

All systems have API access or integration available
Authentication method known (OAuth, API key, service account)
Rate limits documented for each API
Webhook endpoints can be configured
Test credentials available for each system

Security & Compliance

PII fields identified and tagged
Data retention policy defined
Access controls: who can trigger, view, modify
Audit logging enabled on automation platform
Vendor security review completed (if required)

4. Automation Design Checklist

Workflow Architecture

Trigger defined: event, schedule, or manual
Enrichment steps identified (data lookup, AI research)
Decision logic mapped: every if/then/else
Actions specified: create, update, notify, generate, route
Error paths defined for each step
Success/failure notifications configured

AI Integration Points

Where can AI classify/route? (lead scoring, ticket categorization)
Where can AI generate? (emails, proposals, summaries, code)
Where can AI extract? (PDF parsing, email parsing, web scraping)
Prompt templates drafted for each AI step
Fallback: what happens if AI fails/low confidence?

5. Implementation Checklist

Build Phase

Start with template (don't build from scratch)
Configure trigger and test with sample data
Build enrichment chain: primary → fallback → manual
Implement decision logic with visual builder
Add each action step, test individually
Configure AI prompts, test with edge cases

Testing Protocol

Unit test: each step in isolation
Integration test: full happy path
Edge case test: missing data, wrong format, duplicates
Failure test: API down, rate limited, timeout
Load test: 10x expected volume
Security test: PII handling, access control, injection
UAT: end-to-end with real user

6. Validation & Launch Checklist

Pre-Launch

Success metrics dashboard built (time, errors, throughput, cost)
Baseline measurements recorded from manual process
Rollback plan documented (how to revert in 5 min)
Team trained: trigger, monitor, troubleshoot
Documentation: runbook + video walkthrough

Launch Sequence

Day 1: Shadow mode (automation runs, human reviews all)
Day 3: 10% autonomous, 90% reviewed
Day 7: 50% autonomous if >95% accuracy
Day 14: 100% autonomous if >98% accuracy
Daily 15-min standup during launch period

7. Governance & Optimization Checklist

Ongoing Operations

Weekly: review failed runs, error patterns
Monthly: compare metrics vs baseline, calculate ROI
Quarterly: audit all workflows, retire unused, plan new
Annual: platform review, vendor evaluation, strategy refresh

Continuous Improvement

Capture every "why did it do that?" → improve logic
Track AI confidence scores, improve low-confidence prompts
Monitor API version changes, update proactively
Celebrate wins: share time saved, revenue impacted
